# 截止回收与结果分析

适用于用户要求停止填写、查看全部结果、分析问卷或为后续决策提出建议。先读取当前问卷真实题目、填写说明、选项、跳题和最新修改，不能只凭创建时的记忆分析。

## 截止与快照

1. 明确问卷身份和当前登录账号；复用本次真实填写链接和管理入口。同名问卷不猜选。
2. 用户明确要求截止即可执行。只要求分析时保持原收集状态，记录取数时间，并说明报告反映该时点。
3. 优先使用当前官方工具支持的停止收集操作，先读帮助。已实测的某版 `+form-update` 仅能改标题和说明，不支持停止收集；此时用已登录管理页的“设置 → 停止收集 → 停止”完成，不猜未公开接口。
4. 管理端回读状态，再打开真实填写端核实已无法填写（例如“暂不支持填写”）。不提交模拟答案，不删问卷或答卷，不通过撤销整份文档权限假装截止。操作结果未知先回查。
5. 保存截止证据、题目和字段结构、答卷快照、取数时间与时区、数据版本（如有）。截止时间未知不能用下载时间冒充；数据仍变化时记录差异，必要时补取到一致时点。

## 全量读取与对应关系

优先用 `lark-cli`，按当前版本读 `lark-base` 及 `references/lark-base-data-analysis-sop.md`。明确使用获授权的用户身份，不静默换机器人。读取答卷通常需要 `base:record:read`；实际缺项以工具返回为准，不为省事申请全部权限。聚合能力缺权限时单独处理，不冒称已统计。

- 先读取管理端题目、字段定义、题型、选项和表范围，并在可用时核对填写端。停止收集后，填写端题目查询可能因分享已关闭而失败；此时以管理端题目列表及截止前快照核对，不为读取题目重新开放收集。建立“题目顺序／题干／实际字段 ID／底层字段名”的对应表，以实际表单题目的字段 ID 连接答案，不能只凭列名或列位置。
- 特别检查主字段被复用、改名及同题干的空列：题目答案可能存放在名称普通的主字段中，另一个同题干字段反而为空。空列不证明整题无人作答。保留此项核对证据，不擅自搬动原数据。
- 全量导出不依赖默认首屏、已有筛选视图或固定前若干条。原始记录串行分页到明确无下一页，保留每页范围、记录 ID、分页信号和总数；分页游标按工具真实语义使用。
- 同时用云端聚合核对总记录数及需要的分类人数；`count` 是非空计数，`count_all` 才是全行计数。聚合维度行可能已去重，不能当作逐条答卷。不能完成核对时说明实际覆盖，不说“全部看完”。
- 检查记录 ID 重复、空白行、初始化行及题目缺失；只按有证据的规则区分技术重复或测试记录。相同选项或相同文字不等于同一个人重复提交，不能自动删除。无法确认独立填写人数时称“份答卷”，不称“位独立受访者”。
- 原始快照保持不改，另建清洗及编码表，逐项记录排除、归并或更正依据。不将回答内容、姓名或原始记录上传到公共搜索、记忆服务或技能仓库。

## 分母、质量与分组

先声明研究问题和统计口径，再给结果。分别列出原始回收份数、可分析份数、完整作答份数、每题非空份数与适用样本；不要用一个“有效样本”掩盖题目间差异。

- 单选逐项给人数和比例，说明分母，缺失与“其他”“不清楚”单列。比例四舍五入造成合计偏差可注明；零分母不给百分比。
- 多选或开放题多标签按“提及该项的答卷份数”计数，同一份在同标签中只算一次，标签合计可以超过样本数或 100%，不可伪装成单选。
- “过去30天0次”与“最近一次购买原因”可能分别反映近期频次及更早经历，不自动判假答。时间不明就标“时间范围待明”，需要近30天结论时单独限定明确购买者。
- 按本次研究问题区分全体、明确近期购买者、次数记不清但确认购买者、零次或不确定者。展示有决策价值的交叉比较时同时给每组分母和缺失情况，不能把其他组悄悄丢弃。
- 少量或便利抽样只做样本内描述；不虚构显著性、置信度、市场规模或总体购买率。没有邀请人数就不计算回收率，没有提交时长就不声称排除了极速答卷。
- 逻辑张力列为待核线索：不同时间范围、单选“其他”或自由文字中的历史经历均可能解释差异，不修改原答以迎合结论。

## 开放题全文阅读与编码

全文阅读每份开放回答，保存去身份化的逐条编码表，至少能从报告追到原记录。编码表含：内部答卷代号、原文、状态、标准化品类、口味／商品名、吸引原因、编码依据或不确定性。只收集本次解释需要的信息，报告匿名引用。

- “无／没有”、记不清、缺失、离题、仅提口味、笼统品类、具体商品、多品类回答分别编码。保留原文，不把所有未能归入产品的回答统称“没有需求”。
- 品类、口味、商品名分开。仅写“抹茶”不能补成“抹茶贝果”；模糊名称、错字或疑似饮品不能默认为具体甜品。多品类不擅自挑一个，也不把多次提及当作多份答卷。
- “最先想到／知道大概味道”衡量熟悉度及联想，不能直接写成最想买、最喜欢或购买意愿。题目本身没有要求现售时，不据此判断该品牌现售产品结构。
- 自述尝试题区分：明确自述首次尝试且有商品、商品有但吸引原因缺失、只有原因没有商品、没有、记不清、缺失及时间不明。自述尝试不证明商品客观是新品，也不等于销量、喜爱或复购。
- 数量词、否定和上下文一起读：例如“没买过，但看到推荐会想试”只能算潜在想法，不能归入已尝试。已有同类经验也不能自动算本题指定时段的新尝试。
- 每个关键开放题结论给编码人数和一两条有代表性的匿名原话；同时保留反例。没有来源支持的主题只写为研究者假设。

## 分析与交付

报告结构按本次决策需要安排，至少说明：来源及截止状态、样本与口径、逐题人数／比例、开放题归类、必要分组比较、主要发现、限制和下一步。必要时用清楚的统计图或表，不为视觉效果省略分母、零值和样本限制。

每条建议连接“观察到什么 → 可怎样解释 → 提议怎样验证”。事实、解释和研发假设分开。例如，对品类有熟悉联想，只能支持选择测试原型，不能直接决定上新、定价或宣称存在市场机会。建议可指向试吃、价格／份量组合测试、真实点单验证等，缺成本或供应链输入时保留待补。

交付前重算重要人数比例，核对开放题编码与原文，确认报告覆盖全部题目和全部分页，限制与结论强度一致。需要独立复核时提供原始要求、精确数据快照、口径、编码及实际报告，不以作者摘要替代原始证据。工具校验通过不等于业务判断已经被用户确认。

用户要求在飞书交付时创建或更新真实云文档，按工作区长期规则核实负责人管理权限并回读正文。仅获分析授权时不发群、不艾特、不公开答卷、不自动发客户；需要对外发送时另取得覆盖本次报告和目标群的最终确认。

## 可验证情境

- 仅说“分析一下”：保持收集状态，报告取数时点。
- 明确说“截止了，分析所有结果”：真实停止并验证，完整翻页后再分析。
- 主字段存有第四题、同题干空列：按实际字段 ID 读到答案，不报告整题缺失。
- 零次者仍答最近一次：保留历史经历并分组，不一律删卷。
- 多次出现“没有”、两个答卷答案完全相同：保留各份记录，不以文本去重。
- 开放题只有口味或多个品类：保留不确定／多标签，不补造商品或首选顺序。
- 分析完成并更新技能：只发布通用方法，答卷和报告留在本次授权范围。
